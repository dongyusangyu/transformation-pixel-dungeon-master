EXItemSpriteSheet：真实像素边界

下列尺寸按 assignItemRect 的规则计算：保持格子左上角不变， w = 最右非透明像素 x + 1，h = 最下非透明像素 y + 1。 黄线表示编码后的右、下 UV 边界，所有像素按 8×整数倍率显示。

建议裁剪边界 灰色棋盘：透明区域 原始单元：16×16
索引 50（SEAL）在当前 ex_items.png 中完全透明，无法识别真实尺寸。 建议在确认素材前保留 16×16，避免错误裁掉未来绘制内容。

编码实现方案

请选择一种内部实现。三种方案都提供 encode(image,w,h)，差别只在尺寸元数据如何保存。

A

单个 int 位打包（推荐）

低 16 位保存索引，高位保存 EX 标志、w、h；常量自包含，无运行时映射，最接近现有设计。

B

静态 Map 保存尺寸

保留现有数值格式，但增加静态注册表；更直观，却引入初始化顺序与映射同步风险。

C

独立 Frame 元数据表

结构最清晰，但需要改变物品 image 仍为 int 的既有调用链，改动面最大。
