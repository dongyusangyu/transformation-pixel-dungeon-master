# 洛琪希·米格路迪亚法师皮肤全新重绘规格

## 目标与范围

为当前 Pixel Dungeon 项目的法师职业制作一套全新的洛琪希·米格路迪亚皮肤。工作目录必须新建于 `D:/STUDY/Dungeon/skin` 下，最终游戏槽位文件名为 `mage2.png`。本次作品从空白 12×15 画布和项目法师模板开始，不读取、复制、描摹或改造任何旧洛琪希半成品。

`D:/STUDY/Dungeon/skin/phoebe_chubi_cleric_skin` 只用于理解“宽帽檐在 12×15 尺寸下如何保持稳定和可读”的设计原则；不得复制其像素坐标、配色、生成器代码、动作数据或身体轮廓。

## 项目协议

- 目标职业：Mage。
- 输出槽位：`mage2.png`。
- 帧尺寸：12×15 RGBA。
- 精灵表尺寸：256×128 RGBA。
- 有效动作列：0–20；右侧 `x=252..255` 必须透明。
- 有效护甲层：0–6；底部 `y=105..127` 必须透明。
- 七个护甲层必须使用同一组洛琪希外观，逐帧逐像素一致；不因护甲等级改变帽子、披风、发型或衣装。
- 动作与播放顺序遵循 `HeroSprite.updateHeroFrames()`：idle 0–1、run 2–7、die 8–12、attack/zap 13–15、operate 16–17、fly 18、read 19–20。

## 角色设计

采用方案 A“轮廓优先”。角色约二头身，头部占据约一半有效高度，头部直接连接肩部或披风领口，不绘制皮肤色脖颈。

身份锚点按优先级排列：

1. 宽大、横向稳定的黑色尖顶法师帽，帽檐是最强剪影特征。
2. 单一明亮蓝色家族的头发和两侧可读发束；不得混入另一套深蓝发色家族。
3. 黄褐色披风及领口，形成仅次于帽子的主色块。
4. 浅灰白上衣、深海军蓝下装与深色鞋，维持法师职业气质并与披风分离。
5. 半垂眼神和小型浅肤色面部区域；装饰、阴影和发丝不得形成额外眼睛。

调色板控制在约 10–12 个角色颜色：近黑轮廓、黑帽中间色、帽部小面积冷色反光、2–3 个同一家族蓝发色、2 个黄褐披风色、肤色及阴影、浅灰白衣装、深海军蓝衣装。统一采用左上方光源，不使用枕头式包边阴影、半透明抗锯齿或抖动噪点。

## 视图与动作

- Idle 0 为右侧视图，Idle 1 为正面转头。两帧的身体、手臂、披风主体、腿和脚必须逐像素一致，仅头部、刘海、发束与帽顶允许随转头改变；帽檐的整体宽度和基准高度保持稳定。
- Run、Attack/Zap、Fly 为右侧视图。普通侧视动作的双脚脚尖均朝右。
- Run 使用六个真实步态关键帧，至少四种脚部剪影，包含接触、下压、经过和腾空变化；身体只允许 0–1 像素上下起伏。披风下摆和蓝色发束滞后一相位摆动，帽子不独立左右漂移。
- Attack/Zap 使用蓄势、伸展、最大触及三阶段，手保持空手，不新增法杖、武器或其他持有物；第 0 帧承担恢复。
- Operate 16–17 为正面视图，双眼位置固定，由手、肩和披风小幅变化表达操作动作。
- Fly 18 为右侧腾空姿势，腿部折叠或错开，帽子、发束和披风保持可读。
- Read 19–20 为正面视图，双眼逻辑可见；卷轴颜色和坐标逐像素复制法师项目模板。
- Die 8–12 逐帧逐像素复制原始 `mage.png` 的人类法师死亡模板。由于七层外观相同，所有层使用同一份法师死亡序列。

## 测试与质量门禁

实施采用测试驱动方式。先编写并观察失败测试，再实现生成器。测试至少覆盖：

- 精灵表尺寸、RGBA 模式、透明右侧和底部留白。
- 七个护甲层逐帧逐像素完全一致。
- 两个 PNG 输出字节一致。
- 所有活体动作非空，且身份锚点色存在。
- 黑帽宽度、位置和结构轮廓在相同视图的帧间稳定。
- 蓝发只使用指定明亮色族，黄褐披风色块持续存在。
- Idle 只改变头部组，身体组保持逐像素一致。
- Run 至少四种脚部签名、双脚朝右、相邻帧至少三处逻辑区域变化。
- Attack 最大触及满足项目模板边界。
- Operate/Read 正面双眼固定且不存在第三眼信号。
- Read 卷轴坐标和颜色与 `mage.png` 完全一致。
- Die 帧与 `mage.png` 完全一致。
- 至少五张验证蒙版或蒙太奇，以及恰好 56 个 GIF；GIF 尺寸和时序正确。

最后必须在最终一次生成后重新运行皮肤单元测试和 Pixel Dungeon Hero Skin 的 `audit_skin.py`。只有两者均以零失败结束、56 个 GIF 数量正确、最终图和别名字节一致，并人工检查 1×、放大图、run、attack、operate、read 后才算完成。
