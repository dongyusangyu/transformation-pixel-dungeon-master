# 地牢博士 200 题题库接入设计

## 目标

将 `D:\STUDY\Dungeon\tools\地牢博士题库_SPD攻略_初稿_v1.txt` 中整理的
Q001–Q200 接入“地牢博士”连续四选一问答系统。

题干和四个选项可以作为游戏资源发布；正确选项、答案文本和解析不得写入
资源文件，必须保存在 Java 代码中。

## 输入审计

原稿已通过以下结构检查：

- 共 200 题，题号 Q001–Q200 连续，无重复或缺失。
- 每题均包含题干、A/B/C/D、答案和解析。
- 所有答案均指向 A、B、C、D 之一。
- 答案文本均与所指选项一致。
- 所有选项均不超过 18 个字符。
- 难度分布为简单 120 题、中等 60 题、难 20 题。
- 200 题当前均标记为“待审核”；本次按原稿原样接入，不主动改变题目事实。

## 数据拆分

### 可见资源

新增 UTF-8 文本资源：

`core/src/main/assets/quiz/dungeon_doctor_questions.txt`

采用逐题分块格式：

```text
[Q001]
题干=跨局时，药剂颜色与效果如何对应？
A=每局随机对应
B=始终固定对应
C=按职业对应
D=按楼层对应
```

资源文件中的每个题块只允许包含：

- 稳定题号。
- 题干。
- A、B、C、D 四个选项。

不得包含：

- `答案`。
- `答案文本`。
- `解析`。
- 任何可直接或间接推断正确选项的标记。

难度、分类、来源和审核状态目前不参与游戏运行，也不写入发布资源。

### Java 答案注册表

新增 `DungeonDoctorAnswerRegistry`，为每个 Q001–Q200 硬编码：

- 正确选项索引，使用 0–3 表示 A–D。
- 答案解析。

正确答案文本不单独存储，运行时根据正确索引从四个选项中取得，避免同一答案
文本在两处维护。

注册表返回不可变映射，并在注册时拒绝空题号、非法索引及重复题号。

## 加载与合并

`DungeonDoctorQuiz` 在首次请求生产题库时：

1. 通过 libGDX 内部资源 API 读取 UTF-8 题目资源。
2. 解析所有题块。
3. 以题号查询 Java 答案注册表。
4. 合并为不可变的 `List<QuizQuestion>`。
5. 缓存合并结果，后续答题会话复用该题库。

文本解析与资源访问分离：解析器接收普通字符串，因此单元测试无需启动 libGDX
也能验证完整题库。

## 严格校验

生产题库只有同时满足以下条件才可完成加载：

- 题目数量恰好为 200。
- 题号严格覆盖 Q001–Q200。
- 资源题号无重复。
- 每题题干和四个选项均非空。
- 每个选项按 Unicode 码点计数不超过 18。
- 答案注册表恰好包含 Q001–Q200。
- 每个资源题号都有答案，注册表也没有多余题号。
- 正确索引处于 0–3。

解析器遇到未知字段、重复字段、格式错误或缺失字段时直接拒绝该题库，避免静默
错配答案。

## 错误处理

资源读取或校验失败时：

- 通过游戏异常报告机制记录具体错误。
- 生产题库回退为空的不可变列表。
- 玩家点击“开始答题”时沿用现有“题库尚未载入”提示。
- 不记录答题统计，不导致游戏场景崩溃。

## 测试

新增或更新自动测试，覆盖：

- 资源文件恰好包含 200 个题块和 Q001–Q200。
- 资源文件不含答案、答案文本、解析或其他答案字段。
- Java 注册表恰好包含 200 个合法答案。
- 资源题号与注册表题号完全一致。
- 合并后生成 200 个合法 `QuizQuestion`。
- Q001、若干中间题和 Q200 的正确索引、正确答案及解析与原稿一致。
- 重复题号、缺失选项、未知字段、超长选项、缺失答案均被拒绝。
- 现有连续答题、全局统计和地牢博士生成测试继续通过。

## 非目标

- 本次不重新审核或改写原稿题目事实。
- 本次不增加难度筛选、分类筛选或随机抽题数量设置。
- 本次不把正确答案、答案文本或解析放入任何资源文件。
- 本次不修改现有全局答题统计口径。
