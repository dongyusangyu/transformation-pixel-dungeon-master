# 寻宝小游戏短标签与随机结果设计规格

## 目标与根因

竖屏 `WndOptions` 的正文宽度固定为 120，选项使用单行 `RedButton`。当前寻宝按钮同时显示遭遇名称、准确得分、勇气变化和余烬变化，文本宽度超过按钮，因此左右溢出并被窗口裁切。

本次调整不增大窗口，也不改变十步/无限模式、存档、排行或奖励规则。解决方式是缩短选择前的信息，并把不确定结果变成小游戏的一部分：选择前只显示路线性质，选择后再揭示实际数值。

## 选择前界面

中文按钮固定为：

- `安静小径（稳妥）`
- `怪物巢穴（冒险）`
- `遗忘宝箱（豪赌）`
- `扎营休整（恢复）`
- `追随余烬（转化）`

英文按钮使用同样简短的风险提示：

- `Quiet Path (Safe)`
- `Monsters (Risky)`
- `Chest (Gamble)`
- `Camp (Recover)`
- `Afterglow (Convert)`

按钮不再包含 `%d`、准确得分、勇气或余烬数值。当前步数、总分、勇气、余烬和冒险连击仍显示在窗口正文。

## 随机结果

所有区间均包含上下限。`s` 表示生成选项时已经完成的步数，`r` 表示生成选项前的冒险连击。

| 遭遇 | 得分 | 勇气 | 余烬 |
|---|---:|---:|---:|
| 安静小径 | `15～30 + 2s` | 0 | 0 |
| 怪物巢穴 | `50～80 + 4s + 10r` | `-1～-2` | `+1～+2` |
| 遗忘宝箱 | `100～160 + 6s + 15r` | `-2～-3` | `+2～+3` |
| 扎营休整 | `5～15` | `+1～+2` | 0 |
| 追随余烬 | `25～50 + 3s` | `+1～+2` | `-1～-2` |

随机值在 `buildChoice()` 创建选项时一次性生成并存入 `Choice`，玩家点击后直接应用该值，不进行第二次随机。相同种子和相同选择序列必须产生相同结果。

余烬路线仍只在当前余烬至少为 2 时出现，保证隐藏的最大消耗也一定付得起。勇气和余烬继续限制在合法范围内；达到勇气上限时，结算窗口显示实际净变化。

每五步疲劳保持固定：勇气 `-1`、余烬 `+1`。疲劳属于本步最终净变化的一部分。

## 选择后揭示

`TurnResult` 增加 `afterglowChange()`。选择后的正文显示：

```text
上一步：怪物巢穴
得分 +72，勇气 -2，余烬 +1
```

如果同时触发疲劳，追加“（含旅途疲劳）”。勇气和余烬显示选择、上限裁剪与疲劳之后的实际净变化，因此玩家可以直接和新状态核对。

## 不变部分

- 十步寻宝仍只能开始一次。
- 十步奖励档位仍为 0～399、400～799、800 以上。
- 无限模式仍不产生真实奖励。
- 每局分数、最高分和前五名排行的存档方式不变。
- 小游戏继续使用独立的 `java.util.Random`，不消耗主地牢随机序列。
- 不创建新楼层。

## 验证

- 多个种子生成的同类遭遇必须出现至少两个不同结果。
- 每一种遭遇的得分、勇气和余烬始终位于规定区间。
- 同一种子创建的游戏产生完全相同的首步选项数值。
- `TurnResult` 报告实际余烬净变化。
- 中英文五个按钮都不含格式参数，中文按钮长度不超过 10 个字符，英文按钮长度不超过 22 个字符。
- 运行寻宝专项测试和 Android Debug 打包。
