# 洛琪希法师皮肤设计规格

## 目标与范围

为当前 Pixel Dungeon 项目制作一套以《无职转生》洛琪希·米格路迪亚为原型的法师皮肤。开发产物全部保存在 `D:\STUDY\Dungeon\skin\roxy_migurdia_mage_skin`，最终槽位文件名为 `mage4.png`，同时生成可读别名、验证预览和 56 个动作 GIF。本任务不把贴图复制进项目，也不修改皮肤注册逻辑。

## 项目契约

- 项目根目录：`D:\STUDY\Dungeon\transformation-pixel-dungeon-master`
- 法师源贴图：`core/src/main/assets/sprites/mage.png`
- 已实现法师皮肤参考：`core/src/main/assets/sprites/mage1.png`
- 动作协议来源：`core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/sprites/HeroSprite.java`
- 单帧尺寸为 `12x15` RGBA；整图为 `256x128` RGBA；使用 21 列动作帧和 7 行护甲。
- `x=252..255` 与 `y=105..127` 必须完全透明，所有像素均使用硬边 alpha。

## 视觉方向

采用已批准的“方案 A：轮廓优先”。最终角色约为两头身，以大色块和轮廓识别取代无法在 12x15 像素内稳定呈现的服装纹理。

识别锚点按优先级排列：

1. 始终佩戴宽檐黑色尖顶法师帽，帽檐形成稳定的横向轮廓。
2. 使用单一明亮蓝色亮度家族表现齐刘海、侧发和长辫，不混入深蓝发色家族。
3. 黄褐色披风覆盖肩部和躯干，成为除帽子外最大的服装色块。
4. 正面保留两只偏蓝绿色眼睛；侧面只显示一只主眼，并用鼻尖和后脑轮廓表达朝向。
5. 用少量白色领口、深色裙装和浅色靴子补充动画原设，但不得削弱帽子、蓝发和披风三项主锚点。

帽子动作参考 `D:\STUDY\Dungeon\skin\phoebe_chubi_cleric_skin`：帽檐在跑步中保持唯一的归一化横向签名，只允许随身体产生 0–1 像素竖向起伏，并通过帽带或帽顶高光位置表达动作相位。长辫和披风下摆作为柔性部件，比身体运动慢一个相位，不得遮挡手、脚或卷轴。

## 护甲行策略

用户已明确确认 7 个护甲行必须逐像素完全相同。第 0 行是唯一母版，生成后原样复制到第 1–6 行；无甲、布甲、皮甲、锁甲、鳞甲、板甲和职业护甲不使用任何材质差异。该规则覆盖全部 21 帧，包括死亡与阅读帧。

为满足上述规则，死亡动作从 `mage.png` 第 0 行的 8–12 帧精确复制，然后复制到全部护甲行；阅读卷轴采用 `mage.png` 第 0 行的法师卷轴颜色与坐标，并同样复制到全部行。这是对通常“逐行复制同护甲死亡模板”规则的明确例外，但仍使用项目原生法师模板。

## 动作与视角

- `idle` 0：向右侧视。`idle` 1：身体、手臂、腿和脚与帧 0 逐像素相同，只将头部及头戴物转为正面。
- `run` 2–7：六个向右侧视的真实步态，至少四种脚部签名，手脚反相摆动，身体仅允许 0–1 像素起伏。
- `die` 8–12：精确复制 `mage.png` 第 0 行对应帧。
- `attack/zap` 13–15：向右侧视的空手施法动作，依次表现蓄势、前伸和最大触及；不新增法杖、书本或其他手持物。
- `operate` 16–17：正面双眼固定，只改变双手、肩部与披风下摆。
- `fly` 18：向右侧视，腿部收起，帽子、头和躯干保持稳定结构。
- `read` 19–20：正面双眼固定，帧 19 使用小卷轴，帧 20 使用居中展开卷轴；卷轴像素与法师模板一致。

所有普通侧视动作的双脚均朝右；除跑步外，两脚接触高度一致。帽子、头部、躯干和披风肩部属于刚性结构，不允许无意的横向漂移；长辫和披风尾部可以延迟摆动。

## 参考证据与动作概念

在开始像素生成前，从官方角色页及可核查的角色设定/宣传图中保存至少一张正面、一张侧面或三视图，以及一张动作参考到 `figure/reference/`，并在 `rules/reference_sources.json` 中记录原始 URL、保存文件名、检查日期和实际采用的视觉事实。官方角色页为 `https://mushokutensei.jp/character/`。

另用图像模型生成一张原创、非像素画、两头身的洛琪希动作参考图。参考图必须包含至少三种跑步姿势、三种空手攻击/施法姿势、一个正面站姿和一个侧面站姿；所有手必须清晰可见且为空手，不出现法杖、武器、卷轴、书本或其他道具。图像及完整提示词分别保存到 `figure/reference/` 和 `rules/`。该图只用于观察肢体连接、帽子/辫子/披风惯性，不得缩小、描摹或粘贴进最终贴图。

## 生成器与输出

使用 Pillow、整数坐标、RGBA 硬像素和最近邻缩放制作确定性生成器。目录结构遵循 `pixel-dungeon-hero-skin` 技能脚手架：

- `code/generate_roxy_migurdia_mage_skin.py`
- `code/test_generate_roxy_migurdia_mage_skin.py`
- `figure/mage4.png`
- `figure/mage4_roxy_migurdia.png`
- `figure/reference/`
- `figure/verification/`
- `gif/tier_0_no_armor` 至 `gif/tier_6_class_armor`
- `rules/design.md`
- `rules/reference_sources.json`
- `rules/style_notes.json`
- `rules/motion_audit.json`
- `rules/audit.json`

验证预览至少包含：整张动作帧、七行护甲一致性、身份锚点、帽子轮廓、跑步分解、正面动作，以及 1x/放大对比。

## 测试与验收

先编写并观察失败测试，再实现生成器。测试至少覆盖：

- 贴图尺寸、RGBA 模式、透明右侧/底部边距和无半透明像素。
- 两个最终 PNG 字节完全一致。
- 7 个护甲行在 21 个帧区域内逐像素完全相同。
- 所有活动动作非空，帽黑、明亮蓝发和黄褐披风三类主色存在且跨动作稳定。
- 待机帧只改变头部组；操作和阅读保持正面双眼。
- 跑步至少四种脚部签名、真实腿部关节变化、帽檐唯一横向签名。
- 攻击最大触及、双脚朝向和非跑步接触高度符合协议。
- 死亡帧逐字节等于 `mage.png` 第 0 行模板；卷轴坐标和颜色等于法师模板。
- 至少 5 张验证图、恰好 56 个 GIF，且尺寸、帧序列与编码时长正确。
- 外部参考、生成动作参考、提示词和来源记录均存在。

最后运行皮肤单元测试和 `audit_skin.py`。只有两者在最后一次生成后均退出 0、56 个 GIF 完整、别名与槽位贴图字节一致，并完成 1x 与放大预览、跑步、攻击、操作和阅读 GIF 的视觉检查，才视为完成。

## 边界与风险

- 不修改游戏项目中的 sprite、Java、资源注册或本地化文件。
- 不覆盖 `D:\STUDY\Dungeon\skin` 下任何已有皮肤目录。
- `mage4.png` 只是避免与现有外部作品 `mage2`、`mage3` 冲突的交付槽位；未来安装仍需单独复制资源并调整可用皮肤数量。
- 12x15 的像素预算不足以完整表现服装层次，验收优先级固定为帽子、蓝发/辫子、黄褐披风、面部、步态，其后才是内搭与靴子细节。
