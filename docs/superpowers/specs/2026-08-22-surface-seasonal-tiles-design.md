# 第 0 层现实月份季节素材切换设计

## 目标

第 0 层 `SurfaceTownLevel` 根据游戏启动时的设备现实月份选择一整套地表环境素材：

- 3 月至 10 月使用 `tiles_surface_lush.png` 与 `water_surface_lush.png`。
- 11 月、12 月、1 月、2 月使用 `tiles_surface_winter.png` 与 `water_surface_winter.png`。

切换方式是直接选择对应的 PNG 资源路径。地图布局、地形编号、瓦片索引、碰撞、NPC、物品和存档内容均不随季节改变。

## 已确认行为

季节只在游戏进程启动时判定一次。加载存档、进入第 0 层、返回第 0 层或切换存档时均不重新读取日期。

如果游戏在跨月时持续运行，当前会话保持启动时的季节。关闭并重新启动游戏后，立即根据新的现实月份重新判定。例如，10 月启动的游戏即使运行到 11 月仍使用葱郁素材；11 月重启后改用冬季素材。

季节不写入存档。旧存档和新存档使用相同规则，因而不需要存档迁移。

## 素材审查结论

两张地表图集均为 RGBA PNG，尺寸为 `256×256`，按项目标准切分为 `16×16` 瓦片，共 256 个固定槽位。冬季图集与葱郁图集采用相同的瓦片语义和坐标布局，其中 36 个槽位存在可见像素差异，主要位于草地、积雪边缘、湖岸、树木和季节性装饰区域。建筑墙体、门、书架、道路和室内地板等结构槽位保持兼容。

两张水面图均为 RGBA PNG，尺寸为 `32×32`，颜色层级和像素结构一致。冬季水面使用偏冷的蓝色调，与冬季湖岸配色相匹配。

因此本功能不需要复制第 0 层地图生成逻辑，也不需要进行运行时调色或重新映射瓦片。

## 架构

新增一个职责单一的 `SurfaceSeason` 类，放置在第 0 层领域附近。它负责：

1. 在游戏启动时读取一次现实月份。
2. 缓存本次进程使用的季节枚举 `LUSH` 或 `WINTER`。
3. 提供当前季节的地表图集路径、水面图集路径和季节专用纹理缓存键。

`ShatteredPixelDungeon.create()` 在创建首个场景之前调用 `SurfaceSeason.initializeFromSystemDate()`。初始化完成后，所有第 0 层渲染入口只读取缓存结果，不再访问系统时间。

`SurfaceSeason` 默认值为 `LUSH`，作为极早期测试环境或异常启动流程未显式初始化时的稳定回退值。正式游戏启动流程始终显式初始化。

## 资源声明

在 `Assets.Environment` 中保留现有常量并增加：

- `TILES_SURFACE_WINTER = "environment/tiles_surface_winter.png"`
- `WATER_SURFACE_WINTER = "environment/water_surface_winter.png"`

资源常量继续保持不可变。季节切换不通过修改 `Assets.Environment` 的全局字段实现。

## 第 0 层纹理接入点

以下位置必须统一从 `SurfaceSeason` 获取当前地表图集，不能继续写死 `TILES_SURFACE_LUSH`：

- `SurfaceTownLevel.tilesTex()`
- `SurfacePathTilemap`
- `SurfaceGrassTilemap`
- `SurfaceInteriorFloorTilemap`

`SurfaceTownLevel.waterTex()` 从同一季节状态获取配套水面图集。

这保证基础地形、自定义道路、草地覆盖、室内统一地板和湖面在同一帧内使用同一季节，不产生混合素材。

词典图标等不属于第 0 层场景渲染的界面资源不在本次切换范围内，继续保持现有素材。

## 草地净化纹理缓存

当前 `SurfaceGrassTilemap` 会复制地表图集并清理草地槽位中的灰色碎屑色。该逻辑继续保留，但需要改为接收当前季节的源图集路径。

纹理缓存键必须包含季节，例如：

- `surface-town-clean-grass-lush-v1`
- `surface-town-clean-grass-winter-v1`

这样测试期间切换季节或纹理缓存未清空时，不会把先生成的葱郁纹理误用于冬季。像素处理仍只替换已知的葱郁草地碎屑色；冬季图集中不匹配该颜色的像素保持原样。生成纹理继续使用最近邻过滤和无混合像素复制，保证像素画边缘清晰。

## 月份判定接口

系统月份输入统一转换为人类习惯的 `1–12`：

- `1、2、11、12` 返回 `WINTER`。
- `3–10` 返回 `LUSH`。

为了避免 `Calendar.MONTH` 从 0 开始造成边界错误，读取系统日期后立即执行 `+1`，其余季节逻辑只处理 `1–12`。

提供一个不读取系统时钟的月份判定函数供单元测试使用。正式启动入口负责读取 `GregorianCalendar.getInstance()` 并把月份传入该函数。

对于超出 `1–12` 的测试或调用输入，函数抛出 `IllegalArgumentException`，避免静默选择错误季节。

## 数据流

1. 游戏进程启动。
2. `ShatteredPixelDungeon.create()` 调用季节初始化。
3. `SurfaceSeason` 读取当前月份并缓存 `LUSH` 或 `WINTER`。
4. 玩家进入或加载第 0 层。
5. `SurfaceTownLevel` 及三个自定义 Tilemap 读取同一个缓存季节。
6. 基础地形、覆盖层和水面分别加载该季节对应的 PNG 文件。
7. 本次游戏进程内不再重新读取月份。

## 错误处理与兼容性

- 季节状态不进入存档 Bundle，不改变存档格式和版本号。
- 旧存档加载后仅改变视觉素材，不触发地图重建。
- 两套图集尺寸或槽位语义若未来发生变化，应由资源契约测试直接失败，而不是在运行时尝试容错。
- 纹理资源加载失败沿用项目现有资源加载与异常上报机制，不增加静默替代文件逻辑。
- 本设计仅影响第 0 层，不影响高塔、普通地牢和词典界面的环境素材。

## 测试规格

### 月份边界测试

验证以下输入：

- 1 月、2 月为 `WINTER`。
- 3 月、10 月为 `LUSH`。
- 11 月、12 月为 `WINTER`。
- 0 月、13 月抛出 `IllegalArgumentException`。

### 启动期稳定性测试

验证季节初始化后，加载不同存档或多次创建 `SurfaceTownLevel` 都使用同一缓存季节。测试可通过显式月份初始化模拟重启，不依赖测试机器的真实日期。

### 第 0 层一致性测试

分别在 `LUSH` 和 `WINTER` 状态下验证：

- `tilesTex()` 返回正确的地表 PNG。
- `waterTex()` 返回匹配的水面 PNG。
- `SurfacePathTilemap`、`SurfaceGrassTilemap` 和 `SurfaceInteriorFloorTilemap` 使用相同季节的地表 PNG。
- 草地净化纹理缓存键在两个季节之间不同。

### 资源契约测试

验证两张地表图集均为 `256×256` RGBA PNG，两张水面图均为 `32×32` RGBA PNG。图集尺寸变化将导致测试失败，以保护固定的 `16×16` 瓦片坐标契约。

### 既有回归

运行现有第 0 层布局、道路、草地比例、草地噪点清理、NPC 和楼梯测试，确认季节功能只改变纹理来源，不改变生成结果。

## 不在范围内

- 不增加春、夏、秋的独立图集。
- 不根据游戏内日期、种子、存档创建日期或网络时间选择季节。
- 不在游戏运行中热切换季节。
- 不重新生成第 0 层地图。
- 不修改两张已提供的地表图集和水面图。
- 不改变冬季的怪物、NPC、物品、植物、天气或玩法规则。

## 验收标准

1. 3–10 月启动游戏后，第 0 层所有地表相关视觉均来自葱郁素材组。
2. 11–2 月启动游戏后，第 0 层所有地表相关视觉均来自冬季素材组。
3. 游戏运行中跨月或切换存档不会改变当前季节。
4. 重启游戏后立即按新的现实月份选择素材。
5. 同一季节内基础地形、道路、草地、室内覆盖与水面不存在混用另一季节素材的情况。
6. 第 0 层地图布局、交互、存档和生成结果与季节功能加入前一致。
