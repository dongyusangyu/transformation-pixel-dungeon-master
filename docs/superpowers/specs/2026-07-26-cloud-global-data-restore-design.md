# 云端全局数据恢复设计

## 目标

恢复设置界面的“同步服务器数据”按键，为玩家提供一次性云端全局数据恢复能力。恢复以玩家填写的 UUID 为核心身份，兼容应用卸载重装、Debug 包切换到正式包及更换设备等场景。

## 恢复范围

只恢复 `SaveManager` 管理的全局文件：

- `badges.dat`：徽章数据。
- `rankings.dat`：排行榜数据。
- `journal.dat`：物品与怪物图鉴、拾取次数、使用次数、怪物击败次数、天赋统计及其他全局日志统计。
- 云端玩家 UUID：恢复成功后，本地 UUID 更新为实际恢复的 UUID。

不得读取、下载、创建、覆盖或删除 `save-*.json`、楼层文件及任何当前局游戏存档。

客户端对服务端返回的 `global_data` 继续通过 `SaveManager.saveGlobal()` 应用。该方法仅接受徽章、排行榜、日志及云端身份字段，忽略其他未知字段，以维持旧版数据兼容性。

## 客户端交互

1. 在 `WndSettings.DataTab` 中重新加入并布局“同步服务器数据”按键。
2. 点击按键后显示 UUID 输入窗口，本地已有 UUID 时自动填入；没有 UUID 时允许玩家粘贴原 UUID。
3. 输入内容去除首尾空白。留空时通过当前设备指纹自动识别原 UUID；非空内容执行标准 UUID 格式校验，无效 UUID 不发送网络请求并显示明确提示。
4. UUID 输入确认后再显示危险操作确认窗口，明确说明：
   - 只恢复徽章、排行榜、图鉴和日志统计。
   - 不恢复或修改任何局内存档。
   - 云端数据将覆盖上述本地全局数据。
   - 恢复许可只能使用一次。
5. 玩家再次确认后发起恢复。请求期间禁用恢复按键并显示“同步中”。
6. 成功后刷新徽章、排行榜、Journal 与天赋统计缓存，更新设置页显示的 UUID，并提示恢复成功。
7. 找不到 UUID、恢复未授权、网络失败或数据无效时显示可区分的错误文案；失败时不主动更改本地 UUID。

## 服务端流程

恢复请求继续兼容现有 `/api/download` 接口，并优先按请求中的合法 `player_uuid` 查询。对于旧客户端，仍保留设备映射和旧设备字段的回退查询。

当目标玩家不存在或 `restore_allowed` 为 `false` 时，不返回个人全局数据，也不改变设备映射。

当恢复许可有效时，新客户端先发起恢复准备请求。服务端返回全局数据和短期恢复 token，但暂不消费许可或修改设备映射。客户端将响应与 token 写入应用私有的待处理文件后，再发起恢复确认请求。

恢复确认时，服务端在同一数据库事务中：

1. 将该玩家的 `restore_allowed` 更新为 `false`。
2. 将本次请求携带的稳定设备指纹绑定到该玩家 UUID。
3. 将同一 token 标记为已提交，使重复确认请求可长期幂等成功；只有未提交且过期的 token 会被清理。

设备映射重绑应保证当前设备指纹只对应本次恢复的 UUID。若 UUID A 的历史记录占用了该设备主键，应先将 A 改为不冲突的归档设备键；A 的玩家记录和统计仍保留。客户端确认提交成功后，先把本地 `cloudPlayerUUID` 设置为服务端返回 UUID，再应用全局数据。之后该设备上传或同步时均使用恢复后的 UUID。

客户端待处理文件不属于 SaveManager 全局数据，也不属于游戏存档。若网络中断或应用被终止，尚未提交时本地数据保持原状；已经提交时本地身份先保持为恢复 UUID。再次打开网络设置会自动继续确认或重新应用待处理数据，完成后删除该文件。

服务端继续接受没有恢复准备参数的旧版下载请求，并保持旧版一次请求完成恢复的行为；旧客户端不会因本次改动失效。

## 身份兼容性

- 同一安装包重装时，客户端可以通过稳定设备指纹回退识别原 UUID。
- Debug 与正式包签名不同、应用 ID 不同，或设备指纹变化时，玩家通过手工填写原 UUID 恢复。
- 更换设备时，玩家通过手工填写原 UUID 恢复。
- UUID 是可靠恢复凭据；设备指纹仅用于同设备免输入便利，不作为跨安装包恢复的唯一保证。

## 错误与安全边界

- 客户端不得把 UUID 放入日志或异常报告正文。
- 服务端只有在恢复许可为 `true` 时返回玩家个人数据。
- 黑名单逻辑保持原状，不因恢复操作重新计入聚合数据。
- 恢复请求不得调用上传接口或执行取大值合并；恢复结果以服务器已保存的全局数据为准。
- 一次恢复成功后，管理员需要重新授权才能再次恢复。

## 测试

### 客户端

- 设置页包含并布局恢复按键。
- 本地 UUID 能预填；空值使用设备指纹回退，非法 UUID 不发起请求。
- 请求明确使用输入 UUID，而不是残留的本地 UUID。
- 成功响应只写入徽章、排行榜、Journal 和云端 UUID，不写入存档槽。
- 成功后刷新全局缓存并显示新 UUID；失败后保留原 UUID。

### 服务端

- 授权 UUID 可以下载全局数据，随后许可变为 `false`。
- 成功恢复后，请求设备指纹映射到恢复 UUID。
- 未授权、未知或格式非法 UUID 不返回个人数据，也不改变映射。
- 第二次使用同一恢复许可被拒绝。
- 新客户端准备恢复时不消费许可，确认恢复时才消费许可并重绑设备。
- 同一恢复 token 的确认请求可以安全重试。
- 显式填写不存在的 UUID 不回退到当前设备 UUID。
- A 重绑到 B 后，B 能继续上传且 A 玩家记录仍保留。
- 旧客户端按设备映射下载的行为保持兼容。

### 验证

- 运行客户端单元测试与 Java 编译。
- 运行服务端恢复接口测试。
- 使用临时数据库验证授权、恢复、设备重绑和二次拒绝完整流程。
- 确认工作区任何 `save-*.json` 文件在测试前后均未变化。
