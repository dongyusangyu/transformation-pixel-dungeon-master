# 藏品日志、价值描述与测试工具设计

## 目标

在现有 20 件世界藏品基础上完成三项扩展：

1. 玩家查看实际持有的藏品时，在描述末尾显示藏品价值。
2. 日志增加独立的“藏品”类别，记录玩家累计获得每一种藏品的次数。
3. `TestPotion` 窗口增加第 16 个“藏品”分类，可选择生成全部 20 件藏品。

## 描述分流

### 实际藏品窗口

`Treasures.desc()` 保持以下顺序：

1. 具体藏品的历史、时代、文明与特征描述。
2. 藏品稀有度。
3. 随机品质。
4. 价值。

中文最后一行为：

```text
价值:%s
```

其中 `%s` 使用该藏品当前 `value()` 的数值。

### 日志藏品详情

日志不能直接调用包含全部动态元数据的 `Treasures.info()`。`Treasures` 提供
专门的日志描述方法，返回具体藏品类的基础历史描述和该类固定的藏品稀有度，
但不包含：

- 随机品质；
- 藏品价值；
- 当前实例的其他随机信息。

日志界面在基础历史描述和藏品稀有度之后自行追加“获取次数:%s”。该次数来自
持久化的藏品获取统计，而不是日志为展示用途临时构造的藏品实例。

## 日志目录与统计

### Catalog 数据

在 `Catalog` 中新增独立枚举值 `TREASURES`，按贴图顺序登记全部 20 个藏品类。
它不加入 `consumableCatalogs`，而是作为与装备、消耗品、图鉴等并列的日志
顶级类别。

`Catalog` 现有 `seen` 和 `useCount` 数据结构、Bundle 存档格式能够兼容新增
类别：

- `seen` 表示该藏品是否曾被玩家获得；
- `useCount` 对藏品解释为“累计获取次数”；
- 每次成功把一个非堆叠藏品加入玩家背包时增加 1；
- 测试模式继续遵循 `Catalog` 的现有规则，不污染正式日志统计；
- 旧存档未包含藏品键时，所有藏品从未发现、获取次数为 0 开始。

统计发生在实际成功加入玩家背包之后。背包已包含同一对象、收集失败或掉落到
地面均不增加次数。

### WndJournal 界面

`WndJournal.CatalogTab` 的顶部类别按钮从 5 个扩展为 6 个，顺序为：

1. 装备
2. 消耗品
3. 藏品
4. 怪物图鉴
5. 文献
6. 天赋

藏品按钮使用扩展贴图中的第一件藏品图标。藏品页标题显示：

```text
藏品（已发现数量/20）
```

列表按 `Catalog.TREASURES` 的登记顺序显示。未发现藏品沿用现有黑色剪影和
`???` 逻辑；已发现藏品打开后显示基础历史描述、固定藏品稀有度及累计获取
次数，但不显示随机品质或价值。

## TestPotion 藏品分类

`TestPotion` 的 `cateSelected` 增加索引 15：

- 分类列表来自 `Catalog.TREASURES.items()`；
- 分类按钮使用扩展贴图中的第一件藏品图标；
- 物品按钮使用每件藏品自己的 EX 图标；
- 点击创建时仍通过公开无参构造器创建所选类；
- 每次构造都会沿用 `Treasures` 现有逻辑重新随机品质；
- 藏品不可堆叠，因此数量和十倍选项不改变单次藏品实例数量。

分类与物品图标统一使用 `ItemSprite` 路由，以同时支持 `items.png` 和
`ex_items.png`，避免对 EX 图标调用 `ItemSpriteSheet.film`。

## 文本资源

默认及中文资源增加：

- 藏品价值标签；
- 日志“藏品”页标题；
- 日志藏品获取次数标签；
- `Catalog.TREASURES` 标题。

中文价值文本严格使用半角冒号：

```properties
value=价值:%s
```

## 测试

新增或扩展测试覆盖：

1. 实际藏品描述包含价值、藏品稀有度和品质。
2. 日志专用描述包含固定藏品稀有度，但不包含价值或随机品质。
3. `Catalog.TREASURES` 精确包含 20 个藏品类，顺序与贴图一致。
4. 成功获取藏品时计数增加，失败或重复收集同一对象时不增加。
5. Catalog 的 Bundle 存取保留藏品已发现状态和获取次数。
6. `WndJournal` 包含独立藏品类别，并使用日志专用描述。
7. `TestPotion` 第 16 类包含全部 20 件藏品，创建路径调用无参构造器，
   不覆盖随机品质。
